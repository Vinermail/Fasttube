# Fasttube

Быстрый десктопный музыкальный плеер: локальная библиотека + каталог YouTube/YouTube Music. Tauri + Rust-ядро + изолированный Python-микросервис.

> ⚠️ **Проект написан ИИ.** Код и тексты созданы языковыми моделями под присмотром
> владельца репозитория и не проходили промышленного аудита.
> **Использование — на свой страх и риск**

## Возможности

**Воспроизведение**
- Локальные файлы: mp3, flac, wav, ogg, m4a, opus и др.
- YouTube: поиск (веб-каталог + переключатель Music), плейлисты аккаунта, Liked, история, похожие треки
- Очередь с предзагрузкой следующих треков, шафл, повтор (off/all/one)
- Скорость воспроизведения (0.75x–2x), перемотка, громкость
- Стриминг с кэшированием: параллельная загрузка чанками (range-запросы), повторные запуски — мгновенно из кэша
- Sleep-таймер, горячие клавиши, drag&drop папки в окно

**Нормализация громкости**
- Теги ReplayGain (читаются из локальных файлов мгновенно)
- Полный анализ EBU R128 (крэйт `replaygain`, алгоритм ffmpeg) в фоне
- Быстрая предварительная оценка при первом запуске + плавная докоррекция
- Уровни: Off / Light / Medium / Strong

**Библиотека**
- Плейлисты из структуры папок, метаданные и обложки из тегов (lofty)
- Избранное, история прослушивания
- Фильтр и сортировка списка, виртуализация (тысячи треков без лагов)

**Прочее**
- Синхронизированные тексты песен (lrclib.net) с подсветкой
- Панель очереди (переход, удаление, очистка)
- Вход в YouTube через браузер по умолчанию: модальное окно со ссылкой и вставкой заголовков

## Архитектура

```
┌──────────────┐  IPC (команды + события)  ┌──────────────────────────────┐
│ WebView (UI) │ ────────────────────────▶ │ Rust-ядро (Tauri)             │
│ HTML/CSS/JS  │ ◀──────────────────────── │ ├ движок rodio/symphonia      │
└──────────────┘                           │ ├ очередь + prefetch          │
                                           │ ├ downloader (reqwest, range) │
                                           │ ├ кэш/настройки/история      │
                                           │ └ сайдкар-супервизор          │
                                           └──────────────┬───────────────┘
                                                          │ gRPC (localhost, динамич. порт)
                                           ┌──────────────▼───────────────┐
                                           │ Python-сервис (api/)          │
                                           │ ├ yt-dlp: resolve             │
                                           │ ├ ytmusicapi: плейлисты/auth │
                                           │ ├ lrclib: тексты              │
                                           │ └ прокси/DoH-обходы           │
                                           └───────────────────────────────┘
```

- **Rust-ядро** само спавнит Python-сайдкар (`uv`/venv), следит за ним (health-check, рестарт) и убивает при выходе
- **gRPC** (tonic ↔ grpcio) по `proto/player_api.proto` — аудио по нему не гоняется, только метаданные и URL потоков
- **Плеер** декодирует AAC-стримы (itag 140/141) прогрессивно, качает параллельными range-запросами

## Требования

- Rust (stable, 2024 edition)
- Python 3.11+ и [`uv`](https://docs.astral.sh/uv/) — для сайдкара
- Windows 10/11 (WebView2), macOS/Linux — в теории, тестировалось на Windows
- YouTube доступен только через прокси/VPN (см. ниже)

## Запуск

```bash
# 1. Python-окружение (один раз)
uv sync --project api

# 2. Сборка и запуск
cargo run
# или сразу с папкой музыки:
cargo run -- "C:\путь\к\музыке"
```

Генерация gRPC-стабов после изменения `proto/player_api.proto`:

```bash
uv run --project api python -m grpc_tools.protoc -I proto \
  --python_out=api/src/ytapi/pb --grpc_python_out=api/src/ytapi/pb proto/player_api.proto
# protoc emits `import player_api_pb2`, which does not resolve from the
# ytapi.pb package; fix it up after every regeneration:
sed -i 's/^import player_api_pb2 as player__api__pb2$/from . import player_api_pb2 as player__api__pb2/' \
  api/src/ytapi/pb/player_api_pb2_grpc.py
```

## Авторизация YouTube

Оба пути начинаются из одного места: ⚙ Settings → YouTube account → **Sign in**
(или кнопка в баннере «Session expired») открывает модальное окно с двумя
вариантами.

**1. Окно внутри приложения (по умолчанию).** *Open sign-in window* открывает
отдельное окно на `music.youtube.com` с приватным профилем
(`%LOCALAPPDATA%\fasttube\auth-profile`, удаляется после входа). Приложение само
читает куки окна, ждёт непустой `__Secure-3PAPISID`, закрывает окно, стирает его
данные браузинга и передаёт сессию сайдкару. Копировать ничего не нужно; в
модалке видно «Waiting for the sign-in in the app window…», пока окно открыто.
Если Google откажет («This browser or app may not be secure») — модалка покажет
это и предложит второй путь.

**2. Браузер + заголовки (запасной).** Раскрой «Google blocks the built-in
window? Use your browser» → *Open music.youtube.com* → войди → `F12` → **Network**
→ запрос `youtubei/v1/browse` → ПКМ → **Copy** → **Copy request headers** →
вставь в поле → *Connect with these headers*.

В обоих случаях куки уходят в Rust-ядро, шифруются Windows DPAPI в
`%LOCALAPPDATA%\fasttube\auth.bin`, сайдкар получает сессию по gRPC `SetSession`
и держит её только в памяти. Пароль Google в приложение не попадает, файлов с
куками нет; поле вставки очищается при закрытии окна и после ошибки.

Сессия проверяется при старте, каждые 15 минут и перед загрузкой библиотеки.
Если YouTube её отозвал — баннер «Your YouTube session expired» с кнопкой входа,
библиотека не выдаётся за актуальную.

**Выход:** *Sign out* завершает сессию в сайдкаре и удаляет `auth.bin`.
Полностью отозвать сессию можно только на стороне Google:
Account → Security → Your devices.

**Стриминг с аккаунтом:** Settings → *Use the account for streaming*
(по умолчанию **выкл**). Включает подстановку куков из памяти в `ydl.cookiejar`:
Premium-битрейт и контент с возрастными ограничениями, но yt-dlp действует как
твой аккаунт — есть риск ограничений. Когда выключено, резолв анонимный.

## Настройки

- **Audio quality**: Standard (AAC 128kbps) / High (до 256+ kbps с Premium)
- **Use the account for streaming**: куки для yt-dlp (по умолчанию выкл)
- **Normalization level**: Off / Light / Medium / Strong (целевая громкость)
- **Sleep timer**, **Clear download cache**

## Плейлисты

Треки правятся откуда угодно: правый клик по строке даёт «Играть следом», «В
очередь», «Добавить в плейлист…», лайк, «Убрать из плейлиста» и переход к
исполнителю/альбому. «Добавить в плейлист…» — поповер с поиском, галочкой у
плейлистов, где трек уже есть (по снимкам, без сети), и созданием нового.

- Удаление уходит в журнал с задержкой 8 секунд: тост «Отменить» убирает
  операцию до того, как она коснётся YouTube.
- Перетаскивание строки на плейлист в сайдбаре добавляет её туда; внутри
  своего плейлиста перетаскивание и `Alt+↑/↓` меняют порядок.
- Шапка плейлиста показывает «Синхронизировано · N минут назад»,
  «Синхронизация…», «Ожидает сети (N изменений)» или ошибку с «Повторить», а
  также бейдж «Только чтение» для чужого плейлиста.
- Лайк (сердце в строке и в плеере) тоже идёт через журнал: работает без сети
  и отправляется после входа; «Понравившиеся» — такой же список, снятие лайка
  убирает из него трек.

## Приёмка на живом аккаунте

Сценарии, которые нельзя проверить без сети и сессии, собраны в один
`#[ignore]`-тест: он поднимает сайдкар сам, восстанавливает сессию из `auth.bin`,
создаёт приватный плейлист, гоняет добавление/удаление/перемещение через журнал,
имитирует офлайн (убивает сайдкар), перезапуск с неотправленными операциями,
дубликат, чужой плейлист, чужой аккаунт и лайк в обе стороны — и удаляет тестовый
плейлист в конце.

```bash
cargo test --bin fasttube manual_acceptance -- --ignored --nocapture
```

Он трогает аккаунт: создаёт и удаляет один приватный плейлист, ставит и снимает
лайк на одном треке (состояние восстанавливается).

## Кэш треков

Скачанный трек лежит в `cache/<id>.<quality>.m4a`, рядом — `<id>.<quality>.json`
с названием. Загрузка идёт в `<файл>.part` и переименовывается только после
проверки: размер файла должен совпасть с тем, что объявил сервер в
`Content-Range`. Иначе файл удаляется и загрузка повторяется при следующем
запуске трека — недокачанный файл в кэш не попадает.

При старте приложение подметает `cache/` и убирает хвосты старых версий: файлы
ровно в 1 МиБ (так выглядел баг, когда скачивался только первый блок-проба) и
недописанные `.part`.

## Замеры

Тайминги пишутся в stdout приложения (строки `[perf] …`) и в лог сайдкара
(`%LOCALAPPDATA%\fasttube\logs\sidecar.log`, уровень INFO):

- `[perf] resolve_ms=…` — сколько заняло извлечение ссылки на поток (в сайдкаре,
  `cached=true` значит ответ пришёл из кэша резолва);
- `[perf] download_ms=… probe_ms=… ttfb_ms=… mbps=…` — загрузка файла: полное
  время, время до заголовков пробного запроса, время до первого байта тела и
  средняя скорость;
- `[perf] time_to_audio_ms=… cached=…` — от запроса трека очередью до отправки
  `SetPlaylist` в аудио-движок.

Запуск dev-сборки с сохранением этих строк в файл:

```powershell
.\target\debug\fasttube.exe *> "$env:TEMP\fasttube-perf.log"
Get-Content "$env:TEMP\fasttube-perf.log" -Wait | Select-String "\[perf\]"
```

Память по процессам (приложение и python-сайдкар отдельными строками):

```powershell
Get-Process fasttube, python -ErrorAction SilentlyContinue |
  Where-Object { $_.Path -like "*player_llm*" -or $_.ProcessName -eq "fasttube" } |
  Select-Object ProcessName, Id,
    @{n = "WorkingSetMB"; e = { [math]::Round($_.WorkingSet64 / 1MB, 1) } },
    @{n = "PrivateMB";    e = { [math]::Round($_.PrivateMemorySize64 / 1MB, 1) } },
    @{n = "CpuSec";       e = { [math]::Round($_.CPU, 1) } } |
  Sort-Object WorkingSetMB -Descending | Format-Table -AutoSize
```

Сумма по приложению целиком (Rust + WebView2 + сайдкар):

```powershell
$pids = (Get-Process fasttube).Id
Get-CimInstance Win32_Process |
  Where-Object { $_.ProcessId -in $pids -or $_.ParentProcessId -in $pids -or $_.Name -eq "python.exe" } |
  ForEach-Object { [pscustomobject]@{ Name = $_.Name; Id = $_.ProcessId; MB = [math]::Round($_.WorkingSetSize / 1MB, 1) } } |
  Sort-Object MB -Descending | Format-Table -AutoSize
```

## Данные

Всё хранится в `%LOCALAPPDATA%\fasttube\`:

- `cache/` — скачанные треки (`<video_id>.<quality>.m4a`, старые `<video_id>.m4a`
  считаются `standard` и переименовываются при первом обращении) и обложки
- `settings.json`, `history.json`, `favorites.json`, `loudness.json`, `library.json`
  (пины, скрытые, переименования, обложки и свои плейлисты; строки бывают
  локальные — `path` — и с YouTube — `video_id`)
- `playlists/yt/<id>.json` — снимки YouTube-плейлистов, `sync/outbox.json` —
  журнал неотправленных правок
- При первом запуске данные из `player_llm\` (прежнее имя) мигрируют автоматически

Секреты авторизации в репозитории не хранятся: куки лежат только в
`auth.bin` (DPAPI, вне репозитория). Старый `api/browser.json` при первом
запуске импортируется и удаляется; если его сессия уже протухла — просто удаляется.

## Сеть и прокси

YouTube в некоторых сетях режется по SNI (TLS-хендшейк зависает, DNS отдаёт только IPv6).
Сервис умеет:

- автодетект локального прокси (порты 10808/1080/7890) или переменную `YTAPI_PROXY`
- DoH-фолбэк (Cloudflare) для IPv4-резолва

googlevideo отдаёт данные только с заголовком `Range` (иначе ~30 KB/s) — учтено в загрузчике.

## Структура

```
├── proto/player_api.proto     # контракт gRPC
├── src/                       # Rust-ядро (движок, очередь, загрузчик, сайдкар)
├── api/                       # Python-сервис (yt-dlp, ytmusicapi, lrclib)
├── ui/                        # фронтенд (vanilla JS, встраивается в бинарь)
├── capabilities/              # ACL Tauri
└── tauri.conf.json
```
